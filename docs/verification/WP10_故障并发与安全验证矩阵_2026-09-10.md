# WP-10 故障、并发与安全验证矩阵

> 执行日期：2026-09-10  
> 结论：本地模拟试点的关键并发、故障恢复与接口安全行为通过；本结论不代表真实厂商联调、生产容量或生产安全认证。

## 1. 验证环境

- JDK 17；
- MySQL 8.0.41，本地实例中为每个集成测试创建随机命名的一次性数据库；
- Redis 7.4.11，临时密码保护容器、随机宿主端口；
- RabbitMQ 3，临时账号密码容器、随机宿主端口；
- 测试完成后删除临时数据库、Redis/RabbitMQ 容器和测试键；
- 密码只通过环境变量或 Maven 系统属性注入，未写入源码和文档。

## 4. 故障与恢复矩阵

| 故障 | 注入方式 | 可执行证据 | 系统行为 | 结论 |
|---|---|---|---|---|
| Redis 会话缓存读取失败 | Mock 抛出运行时异常 | `MemberSessionServiceTest#shouldUseMysqlAuthorityWhenRedisCacheFails` | 回退 MySQL 权威会话，不默认放行未知会员 | PASS |
| Redis 会话缓存写失败 | Mock 故障注入 | `MemberSessionServiceTest` | MySQL 会话仍成立，缓存失败只记录脱敏告警 | PASS |
| Redis 预留后本地事务失败 | 事务端口故障注入 | `ClaimServiceTest#shouldCompensateReservationWhenLocalTransactionFails` | 尝试释放预留；无法立即释放则进入恢复流程 | PASS |
| 补偿时 Redis 不可用 | Redis 端口故障注入 | `ClaimFailureServiceTest#shouldLeaveClaimCompensatingWhenRedisIsUnavailable` | ClaimRequest 保持 `COMPENSATING`，不伪造 FAILED 完成 | PASS |
| 进程在预留与落库间崩溃 | 构造孤儿预留 | `ClaimReservationRecoveryServiceTest` | 超龄且无 ClaimRequest 的 reservation 被幂等补偿 | PASS |
| Outbox Publisher NACK/异常 | Sender Mock NACK/抛错 | `ClaimOutboxPublishingServiceTest` | PUBLISHING 转 RETRY，指数退避；耗尽后 DEAD | PASS |
| Outbox 租约进程崩溃 | 真实 MySQL 过期租约 | `QingheWp04PersistenceIT` | 其他实例可重新领取过期 PUBLISHING 事件 | PASS |
| RabbitMQ 路由错误 | 真实 RabbitMQ mandatory publish | `QingheWp04RabbitIT` | Publisher 收到不可路由结果，不把事件误标 ACK | PASS |
| 发券持续失败 | 监听器重试耗尽 | `ClaimIssueRabbitListenerTest`、`QingheWp05RabbitIT` | 主队列进入 dead queue，再进入受控 parking；失败事实可定位 | PASS |
| 发券事务中途数据库异常 | 真实事务/Mock 故障 | `QingheWp05PersistenceIT`、`ClaimIssueTransactionServiceTest` | 权益与 Claim SUCCESS 同事务回滚，不出现半张券 | PASS |
| 重复 MQ 消息 | 重复调用同 eventId/claimNo | `ClaimIssueTransactionServiceTest` | 已完成申请直接返回原权益，不重复发券 | PASS |
| 迟到 MQ 消息 | 先令申请失败再投递 | `ClaimIssueTransactionServiceTest#shouldIgnoreLateDeliveryAfterFailureAndRejectConflictingPayload` | FAILED 终态不被迟到消息改写；冲突载荷拒绝 | PASS |
| POS 首次响应丢失 | 重复提交/原请求查询 | `PosBusinessContractSkeletonTest`、Controller 测试 | 使用原 posRequestNo 恢复 PROCESSING/SUCCESS/FAILED，不换号盲重试 | PASS |
| 对账分块处理中断 | 某分块事务失败 | `QingheWp08ImportPersistenceIT` | 已完成块不重做，从未完成块续跑；坏行持续留痕 | PASS |

以上“Mock 故障注入”证明代码分支和状态机；“真实 MySQL/Redis/RabbitMQ”证明基础设施交互。两类证据不互相冒充。

## 5. 安全验证矩阵

| 控制 | 证据 | 结果 |
|---|---|---|
| POS HMAC-SHA256 签名 | `PosRequestAuthenticatorTest`、`PosRightsControllerTest`、`PosReversalControllerTest` | 错签名拒绝；原始 body、method、path、clientId、timestamp、nonce 参与签名 |
| 时间窗与 nonce 防重放 | `PosRequestAuthenticatorTest#shouldRejectReplayAndTimestampOutsideWindow` | 超窗拒绝；同 clientId nonce 只能使用一次 |
| 会员、管理、POS 三边界隔离 | `AuthenticationBoundaryTest` 与全部 Controller 测试 | 会员 Token 不充当管理凭据，POS 凭据不能调用管理入口 |
| 管理权限最小化 | `Admin*ControllerTest` | 按 campaign/store/recon/settlement/operation 权限拒绝越权 |
| 请求号与载荷冲突 | 领取/POS/撤销真实持久化测试 | 同幂等键异摘要返回冲突，不覆盖首次事实 |
| 未知字段、长度、枚举和时间输入 | `QingheApiControllerTest`、`ReconciliationFileParserTest` | 非法输入在领域事务前拒绝；文件级错误不进入正常结算 |
| 敏感日志 | `SensitiveLoggingBoundaryTest` | Token、Authorization、券码、密钥、签名、密码和手机号变量不能传给普通日志；禁止直接控制台输出 |
| 券码保护 | WP-05 权益测试、WP-08 导出测试 | 明文券码 AES-GCM 保存；按 SHA-256 摘要定位；卡包和结算导出不泄露完整券码 |

## 6. 端到端覆盖说明

`QingheSystemJourneyIT` 使用同一个一次性 MySQL 数据库和隔离 Redis 串联：

```text
模板创建 -> 活动草稿 -> 审批 -> 发布 -> 领取 -> Outbox 租约/ACK
-> 发券 -> 卡包 -> 加盟 POS 核销及重放 -> 补贴候选
-> 对账文件导入/匹配 -> 结算生成/确认 -> 脱敏 CSV 导出
```

撤销及其对财务事实的影响由 `QingheWp07PersistenceIT` 在真实 MySQL 中独立覆盖；RabbitMQ 传输由 `QingheWp04RabbitIT`、`QingheWp05RabbitIT` 独立覆盖。系统旅程不把 Mock 传输冒充真实 RabbitMQ。
