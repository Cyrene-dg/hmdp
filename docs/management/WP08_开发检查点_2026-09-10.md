# WP-08 T+1 对账与补贴明细开发检查点

> 日期：2026-09-10<br>
> 状态：`IN_PROGRESS`<br>
> 当前分支：`qinghe/wp08-reconciliation`

## 1. 本次已完成

- 新增 manifest 与 CSV 解析模型，按原始 CSV 字节计算 SHA-256 并先于行解析校验；
- 校验 manifest 字段白名单、schemaVersion、checksumAlgorithm、文件名、批次号、业务日期和行数；
- 严格拒绝 BOM、非法 UTF-8、错误表头、未闭合引号和文件级校验失败；
- 支持 RFC 4180 常用引号、逗号及换行形式；
- 合法行转为结构化对账记录，坏行保留行号、错误码和摘要，不静默丢弃；
- 新增对账批次冲突、文件无效、对账未完成和结算批次变化错误码。

## 3. 当前边界

这里完成的是 WP-08 的文件入口基础，不代表 WP-08 已完成。尚未实现：

- provider + batchNo 的数据库幂等、相同 checksum 重放及不同 checksum 冲突；
- 分块落库、导入进度、坏行审计表和中断恢复；
- 平台核销/撤销事实匹配、差异分类与汇总；
- 加盟候选转 `MATCHED`、生成 `PENDING_CONFIRM` 补贴明细；
- 结算批次确认、版本门闩与导出；
- 真实 MySQL 集成测试及 WP-08 全量 Gate。

因此本分支不得合入 `qinghe/integration`，M4 仍未通过，也不能据此把 T+1 对账闭环写成已完成功能。
