# WP-04 开发检查点（2026-09-09）

> 状态：`DONE`。下一工作包：`WP-05 发券与卡包闭环`。

## 已实现

- 新增会员领取与领取结果查询 API，会员身份只取平台会话，不接收请求体会员号；
- 请求摘要按活动编号和客户端请求时刻规范化计算，相同请求返回首次申请，改变内容返回 `REQUEST_CONFLICT`；
- Redis Lua 在同一原子操作内检查活动窗口、库存、请求幂等和每活动每会员占位，并生成可追踪的 `reservationId`；
- Redis 预留成功后，在同一 MySQL 事务写入 `ClaimRequest(PROCESSING)` 与 `OutboxEvent(NEW)`；任一写入失败则整体回滚；
- 请求线程在数据库受理失败后尝试幂等归还库存和会员占位；补偿后的相同请求必须重新预留，不能在库存已归还的情况下直接补写申请；
- 孤儿扫描按活动读取超时预留：已有申请则清理待扫描标记，无申请才幂等补偿；数据库查询异常时不会猜测并归还库存；
- Outbox 使用 `NEW/RETRY → PUBLISHING → PUBLISHED` 或 `DEAD` 状态，按实例租约抢占并支持过期恢复；
- RabbitMQ 消息使用持久化原始 JSON，记录 eventId、eventType 和 aggregateId，只有 Broker ACK 且未退回才标为 `PUBLISHED`；
- NACK、超时和发送异常按 1—300 秒指数退避，达到最大次数进入 `DEAD`；每次投递保存独立审计记录；
- Outbox ACK 不改变 ClaimRequest 状态，领取仍为 `PROCESSING`，真正创建权益和进入 `SUCCESS` 属于 WP-05；
- V004 增量迁移增加租约归属、最后错误、发布时间和投递尝试表，并提供开发期 R004 回滚；
- Outbox 发布器和孤儿扫描默认关闭，应用迁移并准备好依赖后分别通过环境变量显式启用。
