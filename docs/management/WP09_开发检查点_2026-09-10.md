## 1. 已完成能力

- 提供统一业务链路查询，可按 `claimNo`、`eventId`、`entitlementNo`、`posRequestNo`、`redemptionNo`、`reconBatchNo`、`settlementBatchNo` 还原申请、Outbox、投递、权益、核销、撤销、对账、结算和操作审计时间线；
- 提供持久异常分页入口，覆盖领取 PROCESSING/COMPENSATING 超时、Outbox DEAD、领取死信处理失败、POS 核销失败、撤销拒绝、文件缺失、批次失败、坏行、对账差异和待确认结算超时；
- 提供按活动、最多扫描 500 条的 Redis 孤儿预留只读检查，明确返回扫描截断状态；自动补偿仍复用原有幂等恢复任务，不提供通用改 Redis/改库存入口；
- 提供领取、POS、对账进程内计数，包括接受、拒绝、成功、失败、累计耗时和幂等命中；
- 提供 MySQL 权威状态快照，包括各领域状态积压、对账坏行/差异/缺失/重复和待确认/已确认金额；
- 指标响应明确标注进程计数随实例重启归零，本地接口不冒充跨实例监控、真实 SLA 或生产告警；
- 新增敏感日志架构门禁，禁止青禾生产代码把完整 Token、Authorization、券码、密钥、签名、密码和手机号变量传入普通日志，并禁止直接写进程控制台；
- 复用 `operation:read`、`recon:operate`、`settlement:confirm` 权限边界；对账重试和结算操作继续经过版本门闩及操作审计，不增加通用改表接口；
- 新增高优先级故障卡，记录本地触发条件、责任角色、排查入口、允许恢复动作和禁止动作。

## 3. 业务边界与剩余风险

- 运营入口是后端 API 和排障手册，没有实现完整管理端页面；
- 当前指标是单进程计数与 MySQL 快照，没有接入 Prometheus、Grafana、短信或企业 IM；正式阈值、通知渠道和值班人员仍待真实部署确认；
- Redis 孤儿检查按活动且有扫描上限，避免全量扫 Redis；跨全部活动的聚合监控属于部署侧采集能力；
- Outbox DEAD 和领取死信失败可以定位，但当前没有通用消息重放按钮，避免在缺少审批和审计语义时制造重复发券；
- 本地自动化结果不代表真实客户、真实厂商联调、生产流量、生产部署或 SLA。
